# 分析计划：控制侧在保留测试集上的检验

状态：用户已在对话中逐条确认（2026-09-28）；与 agent2 商量后提交并打标签 `analysis-frozen-control`，然后拆封一次。脚本：`experiments/e2_confirm/run_control_test.py`。

## 1. 检验什么

`spec.md` 的“核心证伪实验”：把在筛选集上挑出的控制相关组件一起关掉，能否在从没用过的题上，专门伤害强干扰题，而且伤害随诱饵的吸引力增加。

## 2. 模型、组件和关法

- 模型：Qwen3-30B-A3B-Instruct-2507，float16，A、B 两个标签的 logit 用 float32 计算（ADR 0003、0004）。
- 组件：`outputs/e1_screen/qwen3-30b-a3b-instruct/screen/selection.json` 中的主控制组（ADR 0005：已排除领域一般组件）。拆封时由 `load_selection` 核对它的哈希。
- 关法：完全均值消融（α = 0），均值来自中性文本（`@0d7cf23__42ae809__fp16.pt`）。
- 打分：`prefix_avg3`，即共用开头只算一次，三种批量各算一次后取平均。

## 3. 数据

M1 保留测试集（`split.csv` 中的 test），第一次拆封。主判定只用颜色题和尺寸题（63 题，其中强干扰 30 题）；字符串题和同义判断题只报告。

## 4. 判定

1. **主判定**：控制效应，即在颜色、尺寸两个任务中分别算“强干扰题的平均损伤减弱干扰题的平均损伤”，再取平均（`damage.effects`）。95% 区间按概念组重抽样 10,000 次得到。区间下界高于 0.20 logit 为“支持”；上界低于 0.20 为“证伪”；否则为“证据不足”。
2. **第二条证伪条件**：损伤量对“诱饵词与题目词的词向量相似度”（M1 的 w2vD1P，标准化后）回归，以任务为协变量。斜率区间的上界不高于 0 即为“证伪”：说明伤害与诱饵的吸引力无关。相似度取自 `data/materials/m1/associations.csv`（SHA-256 `6c8b4f487f39363a257d45b025adfbde098f810bc7e2751494521ddff66a0b92`）。如果斜率无法估计（例如题目不足），报告“无法估计”，不作判定。
3. 两条都不证伪、且主判定为“支持”，才算核心主张在保留测试集上成立。

## 5. 只报告、不作门槛

- 控制效应占完好模型自身干扰效应（同一批题上的 TDS 效应 E）的比例，便于跨模型比较。
- 与 200 组随机组件比较：同类组件、同层（专家还按路由频率匹配），报告达到或超过目标组的组数，以及经验 p 值 (1 + k) / 201。
- 语义题平均损伤、字符串题平均损伤、知识效应。

## 6. 来源核对

- 选择文件的哈希由 `load_selection` 核对；模型、revision、均值文件、精度、打分方式须与筛选时相同。
- 影响分数的核心文件（`common.SCORE_FILES`：消融、均值、打分、损伤、组件、选择规则的代码，以及 M1 的题目、划分、示范、模板和中性文本）从筛选提交到拆封提交必须完全没有改动；其他文件的改动全部记入 `code_changes_since_screen`（agent2 2026-09-28 意见）。

## 7. 之后

知识侧、两类组件的直接比较（H2 的两个差值）和实验三、四，等 M3 编好之后另写计划、另打标签。拆封之后不再根据保留测试集重新挑选控制组件：以后在同一批保留题上计算两类组件之差时，控制组固定为本次的组件，知识组在别的材料上挑出。
